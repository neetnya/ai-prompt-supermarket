# AI 绘画提示词超市

由开源项目 [ai-prompt-supermarket](https://github.com/BFRKQSB7/ai-prompt-supermarket) 改造而来。本地离线的 AI 绘画提示词生成工具：点选标签直接生成提示词，一键切换中 / 英文输出。

## 特性

- **全量标签库**：内置 31.7 万+ Danbooru 中英对照标签（含角色 / 画师 / 版权 / 作品分类）
- **左右双栏主界面**：左列上正面下负面两个提示词框，右列同位置放正负两个胶囊面板，两列行高对齐；胶囊占满面板高度、内部滚动
- **标签库弹窗**：点「选择标签」分类浏览，发色 / 发型 / 眼睛 / 表情 / 身材 / 服装 / 姿势 / 场景 / 画风 / 来源画质 / 媒材 / NSFW 等，部分大类可继续细分（如服装 → 上衣 / 裙装 / 内衣 / 鞋配饰）。分类胶囊上直接写明该类条数
- **全局搜索**：中文、英文、下划线、空格都能搜，覆盖全库
- **全部浏览**：一键查看最常用 1000 条
- **负面提示词**：内置负面词分类，自动分流到负面框
- **输出语言**：默认英文输出，右上角按钮一键切换中文 / 英文；切换只改变输出格式，标签身份、顺序、正负、权重、自由文本均保持不变。英文模式将下划线转为空格（`long_hair` → `long hair`）
- **框内操作**：复制 / 清未识别按钮就在各自文本框的右上角，正负两栏互不影响（清未识别只清本栏未匹配到数据库的原文）
- **拖动排序**：右侧胶囊面板里可直接拖动调整顺序，右键胶囊设权重，`±` 在正负之间翻转
- **中英文回填识别**：正面 / 负面框支持中文、英文、混合文本和 `(标签:1.2)` 权重；未知文本保留原文并标 `?`。含逗号 / 分号的名称支持完整匹配，输出时以双引号保护
- **选中高亮**：切换一级 / 二级分类和搜索时，正负选中状态均正确恢复

## 分类是怎么算出来的，以及它有多不准

**没有「分类」这个数据字段。** 源 JSON 每行只有 `[英文名, 中文名, 分类号, count]` 四列，分类号只有 Danbooru 那五个值（0/1/3/4/5，官方枚举本来就跳过 2），没有第 5 列记录细分归属。所有分类都是浏览器里现算的：

1. **大分类**：`buildCats()` 扫一遍全库。分类号 1 / 3 / 4 直接进画师 / 版权 / 角色；分类号 5 不自动成类，只保留 `CURATED` 里手工点名的两个分类；分类号 0 的才拿英文名去 `AUTO` 里跑正则（`\b(?:black hair|white hair|…)\b`，有词边界），命中就进对应大分类。一个词可以同时进多个大分类（实测 256 个）。
2. **二级分类**：`renderPanel()` 里的 `filterFn`，切二级时现场用**子串包含**过滤：

```js
const kws = subs[activeSub], sp = t.en.replace(/_/g,' ');
if (!kws.some(k => sp.includes(k))) return false;
```

也就是说「某个标签属于哪个小分类」这个问题代码里没有答案，每次点小分类都是对当前列表重新跑一遍 `includes()`。**因此二级分类是不全的**，实测覆盖：

| 大分类 | 词条数 | 至少落进一个二级 | 一个二级都进不去 |
|---|---|---|---|
| 眼睛 / 瞳色 | 56 | 56 | 0（0.0%）|
| 服装 | 4,588 | 4,468 | 120（2.6%）|
| 身材 | 348 | 331 | 17（4.9%）|
| 发型 | 213 | 183 | 30（14.1%）|
| 表情 | 151 | 129 | 22（14.6%）|
| 场景 / 背景 | 417 | 328 | 89（21.3%）|
| 姿势 / 动作 | 1,377 | 1,044 | 333（24.2%）|
| NSFW 专属 | 1,035 | 382 | 653（63.1%）|

具体缺陷：

- **漏**：一个二级关键词都没命中的词，只能在「全部」里看到。例如服装的 `apron` / `robe` / `sarong` / `off-shoulder`，姿势的 `walking` / `all_fours` / `selfie` / `stretching`，场景的 `couch` / `grass` / `by_window`，表情的 `smirk` / `surprised`，NSFW 的 `kissing` / `caressing` / `nude` / `pussy` / `penis`（二级表里只写了 `sextoy` 没写 `sex`，只写了 `penetrat` 没写 `nude`），发型的 `hair_over_one_eye` 全系列。
- **重**：同一标签可以同时落进多个二级，互不排斥。服装 610 个（`swimsuit` 同属「内衣/袜」和「制服/民族」），姿势 60 个（`sitting_on_lap` 同属「站/坐/躺」和「腿部」）。
- **误**：子串匹配没有词边界，`top` 会吃到 `top_hat`，`tear` 会吃到 `page_tear` / `tear_troughs`。
- **缺**：发色、画风 / 质感、质量词、年代 / 日期、角色数量、来源 / 画质、媒材 / 手绘、负面词**没有二级分类**。
- **大分类本身也不全**：31.7 万条里 26.6 万条是画师 / 版权 / 角色；通用词 5 万条中只有 8,532 条能被关键词命中进大分类，剩下约 4.2 万条（带括号的专名、`AUTO_SKIP` 里的漏网专名、关键词没覆盖的）只能靠搜索找到。

要让二级分类真正全量，得给数据加一列归属或外挂 `en → sub` 映射表，在构建期算好；只补关键词只能改善、不能消除漏和重。补关键词的最小改动是编辑 `src/template.html` 的 `SUBS` 后重新 build。

## 用法

```sh
node tools/build.mjs
```

生成 `ai-prompt-supermarket.html`，双击即可使用。代码与 31.7 万条数据全部内联在这一个文件里，不需要服务器或初始化命令，单独拷走也能离线运行。

默认输出英文，点右上角「输出语言」可切中文；正面 / 负面各在自己的文本框右上角复制。

适配 Stable Diffusion 系标签型模型：**NoobAI-XL / Illustrious / Manhwa Style / Pony Diffusion** 等（Danbooru 标签体系）。

## 项目结构

| 路径 | 说明 |
|---|---|
| `src/template.html` | **唯一源码**：HTML / CSS / 业务逻辑，全量数据处只留一行占位 |
| `supermarket_full_tags_317423.json` | 全量数据源，317,423 条 `[en,zh,category,count]` |
| `tools/build.mjs` | 构建与校验脚本，仅用 Node 标准库，无 npm 依赖 |

## 构建与校验

```sh
node tools/build.mjs          # 模板 + 源 JSON → ai-prompt-supermarket.html
node tools/build.mjs --check  # 只读校验，不写文件
node tools/build.mjs --stats  # 只打印数据统计
```

`build` 先校验源数据（行结构、分类号、count、tagKey 唯一），不通过就不落盘。`--check` 重新渲染一遍，与磁盘产物**逐字符比对**，再确认内联数组可解析、每个 `<script>` 能通过编译——忘记 build 或手改产物都会在这里失败。`--stats` 输出条数、分类分布、中文重名 / 标点统计与数据 SHA256，不单独落盘。

脚本兼容 Node 12+。`--check` 的 JS 语法检查需要 Node 14+（页面用了可选链），在 Node 12 上会自动跳过该步并提示。

## 数据约定

条目格式 `["英文名","中文名",分类号,count]`，例 `["long_hair","长发",0,6089154]`。

分类号：`0` 通用、`1` 画师、`3` 版权 / 作品、`4` 角色、`5` meta（Danbooru 枚举本来就跳过 2，没有 6 是因为作废标签没收录）。count 影响热度排序和中文重名决策，不要无依据修改。分类号 5（meta，共 418 条：评论请求、音视频、站点奖励、画师确认、分辨率、来源、媒材等）**不整类展示**，只有 `CURATED` 里点名的 24 条会出现在「来源 / 画质」和「媒材 / 手绘」两个分类里，其余只能靠全局搜索找到——整类铺开时绝大多数词对出图没有意义。只加精选词不必碰数据：改模板的 `CURATED` / `CURATED_ZH` 即可（库里没有的词要在 `CURATED_ZH` 补中文，否则界面显示英文原文）。

展示策略：角色 / 画师 / 版权这三个上万条的专名库默认只显示前 5,000 / 3,000 / 3,000 条，需要点「加载全部」分块加载；其余分类最多几千条，直接全量渲染，没有加载按钮。

## 代码约定

- **身份**：`tagKey(en)` = trim + 转小写 + 连续下划线和空白并为一个空格，`long_hair` / `LONG HAIR` 是同一个标签；连字符、括号等其他字符保留。`selected` 是按插入顺序的 Map，自由文本用 `raw:` 前缀作键。**中文只是显示与输出层，绝不能当 ID**；`CURATED_ZH` 优先于原库中文。
- **回填**：`parsePromptTokens` 是引号 / 转义 / 括号深度的扫描器，并先匹配含分隔符的最长已知名称，**不要换成 `split(',')`**。中文重名按「已选候选 → count 降序 → tagKey 字典序」决定，不含随机性。

## 说明

- 界面只有深色一套主题；页面不写 localStorage / cookie / IndexedDB，刷新后一切回到默认状态（输出语言回到 English）。
- 标签库覆盖成人内容分类；请遵守当地法律与平台规范，勿生成未成年人内容。
