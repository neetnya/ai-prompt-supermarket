# AI 绘画提示词超市

由开源项目 [ai-prompt-supermarket](https://github.com/BFRKQSB7/ai-prompt-supermarket) 改造而来。本地离线的 AI 绘画提示词生成工具：点选标签直接生成提示词，一键切换中 / 英文输出。

TAG数据来自：https://github.com/ffdkj/ffdkj-Danbooru_Tag-Chinese-English-Translation-Table

## 特性

- **全量标签库**：内置 33.7 万+ Danbooru 中英对照标签（含角色 / 画师 / 版权 / 作品分类）
- **左右双栏主界面**：左列上正面下负面两个提示词框，右列同位置放正负两个胶囊面板，两列行高对齐；胶囊占满面板高度、内部滚动
- **标签库弹窗**：点「选择标签」分类浏览，发色 / 发型 / 眼睛 / 表情 / 身材 / 服装 / 姿势 / 场景 / 画风 / 来源画质 / 媒材 / NSFW 等，部分大类可继续细分（如服装 → 上衣 / 裙装 / 内衣 / 鞋配饰）。分类胶囊上直接写明该类条数
- **全局搜索**：中文、英文、下划线、空格都能搜，覆盖全库；支持输入法合成防抖、完全/前缀优先排序以及 `↑` / `↓` / `Enter` 键盘选择
- **全部浏览**：一键查看最常用 1000 条
- **负面提示词**：内置负面词分类，自动分流到负面框
- **输出语言**：默认英文输出，右上角按钮一键切换中文 / 英文；切换只改变输出格式，标签身份、顺序、正负、权重、自由文本均保持不变。英文模式将下划线转为空格（`long_hair` → `long hair`）
- **框内操作**：复制（支持 `file://` 离线降级兜底）/ 清未识别按钮在各自文本框右上角；排序整理 / 一键重置权重在各自标签栏顶栏，正负两栏互不影响
- **拖动排序与分组整理**：右侧胶囊面板可直接拖动排序，点「排序整理」支持按分类一键分组、自定义分组、一键重置权重与撤销；右键胶囊设权重，`±` 在正负之间翻转
- **中英文回填识别**：正面 / 负面框支持中文、英文、混合文本和 `(标签:1.2)` / `(标签)` 权重；标签名中的括号在输出时自动转义为 `\(` `\)`，回填时还原；未知文本保留原文并标 `?`
- **选中高亮**：切换一级 / 二级分类和搜索时，正负选中状态均正确恢复

## 分类是怎么算出来的，以及它的边界

**没有「分类」这个数据字段。** 源库每行只有 `(name, cn_name, category, post_count)` 四列（构建时映射成 `[英文名, 中文名, 分类号, count]`），分类号只有 Danbooru 那五个值（0/1/3/4/5，官方枚举本来就跳过 2），没有第 5 列记录细分归属。分类在浏览器里通过预编译规则计算：

1. **大分类**：`buildCats()` 单次扫描全库。分类号 1 / 3 / 4 直接进画师 / 版权 / 角色（构建期已按热度降序排好，前端零排序）；分类号 5 不自动成类，只保留 `CURATED` 里手工点名的两个分类；分类号 0 拿英文名跑 `AUTO_RE` 词边界正则命中大分类。
2. **二级分类**：`SUBS_RE` 对 `SUBS` 预编译词边界正则（词干保留词形变化，普通词兼容复数，排除 `top hat` 等典型误抓），较原先的纯 `includes()` 误匹配大幅减少，但规则覆盖仍无法做到 100% 互斥与全量。如需补词可编辑 `src/rules.mjs` 的 `SUBS` 后重新 build。

## 用法

```sh
node tools/build.mjs
```

生成 `ai-prompt-supermarket.html`，双击即可使用。代码与 33.7 万条数据全部内联在这一个文件里，不需要服务器或初始化命令，单独拷走也能离线运行。

默认输出英文，点右上角「输出语言」可切中文；正面 / 负面各在自己的文本框右上角复制。

适配 Stable Diffusion 系标签型模型：**NoobAI-XL / Illustrious / Manhwa Style / Pony Diffusion** 等（Danbooru 标签体系）。

## 项目结构

| 路径 | 说明 |
|---|---|
| `src/template.html` | HTML 骨架与内联占位符 |
| `src/style.css` | 全部样式（深色主题、弹窗、Toast、权重编辑器） |
| `src/rules.mjs` | 精选分类 `CURATED`、自动归类 `AUTO`、翻译补丁 `CURATED_ZH`、二级分类 `SUBS` 与预编译正则 |
| `src/parser.mjs` | `tagKey`、括号转义与提示词回填解析器 |
| `src/app.js` | 状态管理、惰性索引、弹窗渲染、拖拽排序、排序整理、全局搜索 |
| `tools/build.mjs` | 构建与校验脚本，仅用 Node 标准库（`node:sqlite`），无 npm 依赖 |
| `tag.sqlite` | **全量数据源**：`tags(name, category, cn_name, post_count)`，337,393 条 |

## 构建与校验

```sh
node tools/build.mjs          # 模板 + src/* + tag.sqlite → ai-prompt-supermarket.html
node tools/build.mjs --check  # 只读校验，不写文件
node tools/build.mjs --stats  # 只打印数据统计
```

`build` 先从 `tag.sqlite` 的 `tags` 表按 `post_count DESC, rowid ASC` 读出全量行，再校验（行结构、分类号、count、tagKey 唯一），不通过就不落盘，并通过 `JSON.parse("...")` 内联以提升浏览器解析速度。`--check` 重新渲染一遍，与磁盘产物**逐字符比对**，再确认内联数组可解析、每个 `<script>` 能通过编译。

构建依赖 Node 内置 `node:sqlite`，需 **Node 22.13+**（23.4+ 亦可；更早的 22.x 需加 `--experimental-sqlite`）。

## 数据约定

条目格式 `["英文名","中文名",分类号,count]`，例 `["long_hair","长发",0,6089154]`。

分类号：`0` 通用、`1` 画师、`3` 版权 / 作品、`4` 角色、`5` meta（Danbooru 枚举本来就跳过 2，没有 6 是因为作废标签没收录）。count 影响热度排序和中文重名决策，不要无依据修改。只加精选词不必碰数据：改 `src/rules.mjs` 的 `CURATED` / `CURATED_ZH` 即可。

展示策略：角色 / 画师 / 版权这三个上万条的专名库默认只显示前 5,000 / 3,000 / 3,000 条，需要点「加载全部」分块加载；其余分类最多几千条，直接全量渲染。

## 代码约定

- **身份**：`tagKey(en)` = trim + 转小写 + 连续下划线和空白并为一个空格，`long_hair` / `LONG HAIR` 是同一个标签；连字符、括号等其他字符保留。`selected` 是按插入顺序的 Map，自由文本用 `raw:` 前缀作键。**中文只是显示与输出层，绝不能当 ID**；`CURATED_ZH` 优先于原库中文。
- **回填**：`parsePromptTokens` 是转义 / 括号深度的扫描器，并先匹配含分隔符的最长已知名称，**不要换成 `split(',')`**。中文重名按「已选候选 → count 降序 → tagKey 字典序」决定，不含随机性。

## 说明

- 界面只有深色一套主题；页面不写 localStorage / cookie / IndexedDB，刷新后一切回到默认状态（输出语言回到 English）。
- 标签库覆盖成人内容分类；请遵守当地法律与平台规范，勿生成未成年人内容。
